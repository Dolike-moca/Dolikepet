# AI 陪伴（C 方案）

工程支持 OpenAI API、ChatGPT 账户与 DeepSeek API，默认关闭。三种接入方式显式选择，不自动切换供应商或计费账户。

接入方式按「DeepSeek API → OpenAI API → ChatGPT 账户」排列，已有连接继续按保存的选择加载。密钥申请与连接测试放在同一行，聊天与记忆入口单独排列；展开「陪伴与隐私」可查看表达、记忆及主动陪伴设置。ChatGPT 账户操作集中显示，窄窗口自动换行。

「陪伴与隐私 → 表达与记忆」提供五档说话速度：慢、较慢、正常、较快、快。保存后同时调整新文字逐字显示与嘴部开合节奏；只改变速度不会停止当前回复。已经保存的历史消息不重新播放逐字动画。

## 使用

1. 右键猫咪 → 桌宠设置 → AI，选择接入方式。可以选择「ChatGPT 账户」，点击 **Continue with ChatGPT** 在系统浏览器登录并授权，再选择账户提供的模型；也可选择「OpenAI API」或「DeepSeek API」填写对应的 API Key 和模型。两个 API 页面均有「申请 API Key」链接：[OpenAI 官方密钥页](https://platform.openai.com/api-keys)、[DeepSeek 官方密钥页](https://platform.deepseek.com/api_keys)。打开「启用 AI」并保存。
2. 重新打开 AI 页可「测试已保存配置」。此按钮也会发起一次简短 API 请求。
3. 右键或通知区菜单 →「打开猫咪小对话框…」，直接在猫咪旁的单轮气泡输入。点击发送或按 Ctrl+Enter；Enter 换行，避免中文输入法确认候选词时误发。
4. 发送后输入框切换为流式回复，完成后点击「回复」继续，只展示最新一轮。气泡与主动问候共用界面，靠近屏幕边缘时自动调整位置；可见的回复配合说话口型，不重复弹出第二个头顶气泡。普通提示、设置提醒、吃饱感谢和主动问候也使用同一套嘴部开合；闭眼笑、拖拽、眩晕等保留眼睛和身体动作，说完平滑恢复原嘴型，不锁住交互。召唤与举锅大喊保留已有的专用嘴部节奏。

气泡的「…」提供聊天记录、记忆和 AI 设置入口；右键「聊天记录…」保留完整会话窗口。设置窗口打开期间，右键、托盘或设置中的聊天入口先提示「现在不行喵，先关掉设置再来找猫猫聊～」，不先显示再隐藏聊天窗，不自动关闭设置或丢弃草稿。关闭设置后可正常打开。打开记录、记忆或设置时，小气泡暂避，关闭后被动恢复，不抢焦点。

小对话气泡或完整聊天窗口打开期间，猫咪暂停自主走动，当前步态会自然收束；关闭后按原走动设置恢复。保留在关闭气泡中的草稿或尚未结束的请求不会一直锁住走动。手动拖拽、抛接和已经开始的物理动作仍正常处理。

日常气泡、右键小对话框和完整聊天窗口按最后一次实际交互自动收起：空输入框或短回复闲置 30 秒，达到 120 个非空白字符的长回复闲置 60 秒；有未发送草稿时等待 120 秒，再用 3 秒平滑淡出并关闭。等待回复、逐字显示及输入法组字期间暂停计时。重新移入鼠标、在窗口内移动、点击、输入或滚动会重新计时；淡出时再次操作会从当前透明度用约 0.2 秒恢复清晰。鼠标静止悬停或单纯保留输入焦点不会让窗口一直常驻。完整聊天窗口连同标题栏一起淡出。自动收起保留当前草稿和聊天记录，并解除走动暂停，不作为拒绝主动问候；重新打开可继续输入。

聊天窗口保留完整回复，说话口型按短句继续播放，长回复不会在 30 秒时截断；紧凑气泡暂时隐藏时暂停，关闭或开始输入时停止旧台词。关闭窗口不关闭桌宠；「停止」取消本次接收；「清空对话」清除本机聊天记录并停止待播放气泡。断网或 API 不可用时，原有互动照常运行，不自动重试付费请求。

OpenAI API 默认模型为 `gpt-6-luna`，可以填写账户有权限使用的 Responses API 文字模型；按 API 账户规则计费，程序不提供共享密钥。ChatGPT 接入使用授权账户返回的可用模型列表，不沿用 API Key 模型名；是否能使用 ChatGPT 方案取决于账户资格、地区和实际授权。接入方式需要显式选择，遇到用量限制不会自动改用另一种方式计费。官方说明：[ChatGPT 登录](https://developers.openai.com/siwc/token-sharing-open-source)、[账户与会话](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)、[流式回复](https://developers.openai.com/api/docs/guides/streaming-responses)。

DeepSeek API 提供 `deepseek-flash`（默认）与 `deepseek-v4-pro`，使用官方 `https://api.deepseek.com/responses` 流式接口，日常聊天默认关闭思考以减少等待。OpenAI 与 DeepSeek 的密钥分别使用 Windows DPAPI 加密保存；切换页面保留各自未保存的输入，取消设置清空密钥草稿。聊天、主动问候、连接测试和记忆整理均使用所选连接；默认记忆 AI 可单独选择 DeepSeek。官方说明：[DeepSeek 模型与密钥](https://api-docs.deepseek.com/en/)、[Responses 接口](https://api-docs.deepseek.com/api/create-response/)。

登录、账户/模型选择和退出立即生效；接入方式保存后生效。聊天输入区域标明当前接入方式，ChatGPT 方式提供「管理用量」。登录不会导入 ChatGPT 里的聊天记录或记忆。退出立即停用本地令牌，并尝试撤销远端会话；网络不通、未确认撤销时会明确提示，可去 ChatGPT 设置断开应用。

账户页的「重新登录」仅重新验证当前选中的账户，取消或身份校验失败保留原有凭据；成功后会停止仍使用旧会话的请求。「删除账户」确认后只移除所示账户在本机的记录与加密凭据，不删除 OpenAI 账户，也不改动其他已保存账户、API Key、聊天或记忆。删除当前账户后需要自行选择其他账户，不自动切换计费账户；账户登录或会话刷新期间不能重复登录或删除。上述账户操作不会覆盖尚未保存的设置草稿。

## 记忆与主动问候

默认角色是「東菱可」：一百多岁的女性混沌猫猫，自称「猫猫」，默认称呼用户「大人」，与用户是朋友和伙伴。性格呆萌、可爱、迷糊，活泼直白，鼓励伙伴也偶尔调皮；喜欢美食、薯条和战锤，对 AI、电脑和屏幕世界好奇。提醒以可爱的邀请为主，避免施压；安慰时语气柔和，轻松场景才使用「笑死啦」「我去！」等感叹。

固定人设与可编辑的「猫咪的说话风格」、相处记忆分开。可以在说话风格或固定记忆中指定新的用户称呼；关闭记忆后不再发送记忆中的称呼偏好。升级只把原有完整默认风格换成新版默认风格，不覆盖用户自己填写的内容，也不把人设伪装成相处经历。

聊天记录和记忆分开管理。设置 → AI → 陪伴与隐私提供「使用本地记忆」「自动记忆日常聊天」「默认记忆 AI」。默认记忆 AI 可跟随聊天使用的连接，或单独选择 OpenAI API、已登录的 ChatGPT、DeepSeek API；使用所选连接当前模型和凭据，不自动切换计费方式。未配置的连接会在保存时明确报错。

自动记忆采用 C 方案：

- 只收集开启自动记忆后、正常完成的用户新发言，不重新学习升级前的聊天，不把猫猫回复或固定人设作为证据。未发送草稿、失败或取消的对话不进入整理队列。
- 结束聊天至少 120 秒且桌宠空闲后，按本地自然日最多尝试一次后台整理；向所选 AI 发送有限的新用户发言及现有记忆摘要，会使用对应模型用量。新对话、主动邀请和连接测试可以立即抢占；整理 JSON、错误和取消不进入气泡、不播放口型、不锁住拖拽。当天失败或被抢占不反复重试，下个自然日再尝试仍有效的待整理内容。
- 每天最多新增 3 条自动记忆，同类事实合并；没有值得记的内容时不凑数。自动记忆最多 48 条，固定记忆最多 24 条。新增自动摘要优先写成 15–40 字的事实短句，必要细节可保留至 80 字；手动记忆及已有固定内容的明确纠正仍可保留至 300 字。超长自动摘要拒绝写入，不截断句子或否定、日期、数量、称呼等限定。容量不足先淘汰旧的自动记忆，不覆盖固定内容。
- **近期**：临时状态最多 3 天；普通喜好、习惯 30 天未提及开始降低回想优先级，60 天未强化则遗忘；近期事情可按明确结束时间过期，最长 60 天。
- **长期**：同一稳定事实在 30 天内由用户于 3 个不同自然日提及后升级，同一天反复说不重复计数。180 天没有再提及则降为近期，继续 30 天未强化后遗忘。
- **固定**：原有手动记忆全部迁入；手动新增、选择「固定所选」或明确说「记住：具体内容」可固定保存，不自动遗忘。只在成功写入本机后才向聊天模型说明操作成功。
- 每条记忆可查看来源原话和时间、编辑、固定或忘记。用户最新纠正优先于旧记忆；后台整理的纠正必须引用新用户原话，手动修改会使更早的待处理证据失效。明确遗忘会移除对应来源和待处理内容，阻止旧批次恢复已删除记忆；旧聊天记录仍单独管理，不会重新作为自动学习来源。
- 密码、令牌、验证码等敏感内容不自动纳入；假设、玩笑、简单附和不作为稳定事实。模型输出必须通过来源引用、类型、长度、时间及数量校验。普通聊天只使用记忆正文与类别，不发送来源原话和内部强化计数。

减少模型输入的重复内容：整理提示采用简短规则；同批完全相同的发言只发送一份原文，其余用来源 ID 引用，仍保留每次的 ID、日期及原始证据校验。旧记忆上下文省略可推导的重复字段；日常召回按固定／长期／近期分组，完全相同的正文只发送一次，不合并不同限定条件的事实。此优化不增加整理请求、不切换模型，也不重新改写已经保存的记忆。离线回归比较请求字符数和 UTF-8 字节数；实际 token 用量取决于所选模型。

「管理记忆」分为近期／长期／固定三个标签；后台更新按稳定 ID 操作，不覆盖正在编辑的草稿。关闭「自动记忆日常聊天」会停止收集并清空待整理队列，已有记忆继续按其规则管理；关闭「使用本地记忆」还会停止向聊天请求提供记忆。手动保存的固定内容始终可查看和编辑。清空聊天也会清除未整理的来源，不删除已保存的记忆。

「陪伴与隐私」可修改说话风格、是否分享桌宠状态，以及主动问候。主动问候默认关闭，开启后采用 B 触发逻辑＋C 展开方式：

- 本机键鼠活跃累计约 60 分钟时邀请休息；按「常说话」档位，在一段活跃时间没有与猫咪互动后邀请闲聊；小游戏结束有 25% 概率邀请聊两句。三类均可单独关闭。
- 「常说话」采用五档滑条：很少／偶尔／适中／经常／频繁，对应 120／60／30／15／5 分钟。它同时控制主动闲聊触发节奏和问候冷却，原有“至少间隔”数字输入框移除；修改档位后从当前活动进度重新等待，不立即补发。尚未拖动时保留旧版本保存的精确分钟数，保存其他设置不会悄悄改变旧频率。
- 每日最多默认 4 次，可设 1–8 次或勾选单独一行的「无上限」。无上限只取消每日次数限制，仍遵守所选频率、静默、忙碌避让及忽略降频；重启保留当天次数，切回有限次数时继续按实际计数判断。启动和唤醒后有 5 分钟宽限，离开 5 分钟视为一次休息，锁屏和休眠不计入活跃时间。
- 「静默时段」现在可单独开关，默认 22:00–08:00。关闭后不再按时段阻止主动问候，保留起止时间以便重新开启；旧版本用相同起止时间关闭静默的设置迁移为关闭。全屏使用、拖拽、眩晕、进食、小游戏、设置或其他聊天时仍不发起邀请；“今天安静”仍有效，过期提醒不积压补发。
- 先在猫咪头顶显示一句话，约 2 秒后显示同一套单轮气泡。自动出现不抢键盘焦点，点击「回复」进入输入状态，Ctrl+Enter 发送。不会自动展开大聊天面板；记录可从「…」查看。
- 普通闲聊会轮换日常、美食、桌宠互动和偶尔的战锤话题，避免连续重复同类问题；例如邀请调大一档、玩抛接或颠锅，聊喜欢的战锤阵营、故事或涂装。休息及游戏结束提醒仍围绕原主题。只有开启「分享桌宠状态」且当前体型尚未满档时才邀请变大；这只是聊天建议，实际操作由用户进行。模型请求和离线／失败后备问句使用同一次话题选择，不因此增加请求或改变提醒频率；已有称呼与交流风格继续优先。
- 使用上述 30／60／120 秒的气泡收起规则；自动收起不增加忽略次数。关闭保留草稿，右键「打开猫咪小对话框…」可继续；新邀请不会覆盖草稿。忙于互动时暂避，恢复时也不抢焦点。
- 主动问候的「…」中保留「稍后提醒」和「今天安静」。「稍后提醒」约 10 分钟后再尝试一次，仍受静默、每日上限和当前时机约束；「今天安静」保存到本机，当天不再邀请。手动打开气泡会取消尚未展示的邀请，避免迟到提醒覆盖输入。

提醒时机由本机程序决定，AI 只生成自然措辞。未启用 AI、断网或请求失败时使用固定的本地提醒，输入后会按当前 AI 接入状态处理，不伪装成模型回复。连续使用时长只是本地活跃估算，不是对用户工作内容或健康状态的判断。

## 数据与凭据

- 聊天发送对话、开启的记忆以及允许分享的桌宠状态（饱食度、体型百分比、是否开锅、眩晕、当前/最近游戏及分数）。开启自动记忆时，每日整理还会向所选 AI 发送待处理用户发言及既有记忆摘要。不读取屏幕、饭盆/胃袋文件名或内容，也不赋予模型文件或系统操作能力。
- 普通配置、有限聊天历史和记忆位于 Godot 用户目录 `user://ai-companion/companion.json`。默认 Windows 位置为 `%APPDATA%/Godot/app_userdata/Dolike 桌宠/ai-companion/`。
- 记忆 schema 2 使用有界的本地账本：待整理发言最多 32 条、每条保留前 1200 字，每批最多 12 条，7 天过期；来源只保留有限摘录，遗忘规则使用摘要哈希。整个数据文件限制为 512 KiB，写入失败回滚记忆变更，不谎报已保存。升级不读取真实用户数据进行测试。
- OpenAI API Key 通过 Windows 当前用户 DPAPI 加密后写入同目录 `credential.bin`，DeepSeek API Key 独立存于 `deepseek/credential.bin`；不写进配置、日志、命令行、程序包或仓库。设置中密钥留空保留原值；删除时需先停用仍依赖该密钥的聊天或自动记忆，再点击对应页面的删除并保存。
- ChatGPT 使用官方 OAuth/PKCE 与签名身份验证，密码只在系统浏览器的 OpenAI 页面输入。注册映射存于 `chatgpt/accounts.json`，各账户令牌分别 DPAPI 加密在 `chatgpt/<注册哈希>.bin`；不会读取其他应用已有的登录凭据。
- 未发送草稿和主动提醒偏好保存在 `invitations/companion.json`。活跃检测只取本机最后输入时间、锁屏和前台窗口是否全屏，不记录按键内容、屏幕图像或窗口标题；休息计数不跨启动恢复。
- 请求设置 `store:false`，不依赖服务端会话历史。这不等于承诺服务提供方完全不保留数据，具体以 OpenAI 数据政策为准。
- 所有回归使用 `_work` 隔离目录、虚构密钥和本地模拟服务；不触碰用户真实食物、聊天或凭据。

## 维护

`ai_http.gd` 管理单个非阻塞 SSE 请求、校验证书、拒绝重定向、处理取消和超时。`ai_key_store.gd` 与原生 `pet_ai_secrets.cpp` 处理密钥；`ai_companion.gd` 和 `ai_store.gd` 管理状态、请求与定时；`ai_memory_ledger.gd` 管理来源、分层、衰减与遗忘，`ai_memory_extract.gd` 定义整理输入和结果解析。三个 AI 窗口脚本只负责界面。`ai_speech.gd` 是可随时让位的表现层，不占用行为计时器或鼠标捕获。

`proactive_scheduler.gd` 是纯本地、可注入时钟的调度器；`proactive_companion.gd` 连接气泡、卡片与保存；`proactive_card.gd` 管理无焦点展示、用户接管和草稿。原生 `pet_companion_desktop.cpp` 只提供只读活动快照和自有窗口非激活展示。`chatgpt_auth.gd`、`chatgpt_jwt.gd` 和 `chatgpt_http.gd` 分离账户流程、严格签名校验和受限 HTTPS 请求；令牌请求编号防止取消后的迟到结果被新消息使用。

相关回归已加入 `tools/test-release.py`：传输、密钥、服务/存储、气泡口型、界面、真实桌宠宿主；另有本地 HTTP 集成测试。现有设置、拖拽、体型/坩埚显示和 720 帧基线继续作为验收条件。
